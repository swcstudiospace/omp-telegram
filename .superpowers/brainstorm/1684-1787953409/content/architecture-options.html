OMP Telegram Extension Options

Choose the control model that best matches how you want to run sessions day to day.

Option A: Command Relay
Telegram Group -> OMP Extension
Reply to completion post
Route command to active session
Post terminal screenshot on completion

Option A

Smallest change: replies on a session post deliver OMP commands and guarded shell actions into that live session.

Pros

  • Fastest to ship
  • Fits current code
  • Low complexity

Cons

  • Weak audit model
  • Limited queueing
  • Harder recovery if session dies
Option B: Broker Control Plane
Telegram Group -> Broker Daemon
Session roster
Command queue + audit log
Terminal capture worker

Option B

Make the local broker the authority for session bindings, OMP command dispatch, terminal screenshots, and Telegram acknowledgements.

Pros

  • Clear extension boundary
  • Good auditing
  • Best fit for multi-session ops

Cons

  • More implementation work
  • Needs terminal adapter design
Option C: Durable Job Orchestrator
Telegram Group -> Queue -> Workers
Persist commands and snapshots
Retry, replay, history, automation hooks

Option C

Treat Telegram as a full remote operations surface with durable jobs, event history, and stronger restart behavior.

Pros

  • Most robust
  • Excellent history
  • Future automation ready

Cons

  • Largest scope
  • Slowest to deliver
  • Overkill for first release

Recommendation

Option B is the right target for a proper extension: keep reply-only targeting in Telegram, but centralize command parsing, guarded execution, terminal screenshot capture, and audit events in the broker.
